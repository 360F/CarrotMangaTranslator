# RoverCMT Project Vision
마지막 수정일: 2026-10-03

## 1. 프로젝트 목적

RoverCMT는 자동 만화 번역 시스템이다.

RoverCMT의 핵심 번역 기능은 특정 데스크톱 운영체제에 종속되지 않는 방향을 지향하며,
Linux 환경에서도 독립적으로 실행할 수 있어야 한다.

주된 목표는 정교한 번역 편집 환경을 제공하는 것이 아니라,
원문 만화를 가능한 적은 개입으로 빠르게 처리하여
읽을 수 있는 번역 결과물을 생성하는 것이다.

RoverCMT는 번역 과정 자체보다
사용자가 실제 결과물을 얻기까지의 전체 과정을 중요하게 본다.

---

## 2. CarrotMangaTranslator와의 관계

RoverCMT는 CarrotMangaTranslator에서 출발하며,
기존 프로젝트에서 이미 구현되고 검증된 가치 있는 기능과 알고리즘을
적극적으로 분석하고 재사용한다.

그러나 CarrotMangaTranslator의 모든 기능,
내부 구조 또는 workflow를 유지하는 것을 목표로 하지 않는다.

기존 구현을 유지하기 위해 RoverCMT의 단순성,
성능 또는 개발 용이성을 크게 희생하지 않는다.

RoverCMT는 궁극적으로 독립적인 프로젝트로 동작할 수 있어야 한다.

---

## 3. 제품 철학

RoverCMT는 자동 처리를 기본 workflow로 한다.

기본적인 처리 흐름은 다음과 같다.

Input
→ Detection
→ OCR
→ Translation
→ Erase
→ Typography / Layout
→ Render
→ Output

정상적인 자동 처리 과정에서
사람의 확인이나 완료 승인이 필수 단계가 되어서는 안 된다.

처리에 필요한 데이터가 준비되었다면
가능한 즉시 결과물을 생성할 수 있어야 한다.

수동 검토와 수정 기능을 제공할 수 있지만,
자동 pipeline을 완료하기 위한 필수 조건으로 만들지 않는다.

---

## 4. 핵심 우선순위

### 자동화

가능한 많은 작업을 사용자 개입 없이 처음부터 끝까지 처리한다.

### Time-to-output

개별 단계의 성능뿐 아니라
입력부터 실제 결과물이 생성될 때까지의 전체 시간을 중요하게 본다.

### 단순성

기능의 수보다 구조의 이해 가능성을 중요하게 본다.

필요하지 않은 상태 관리, abstraction, compatibility layer,
중복 데이터 모델과 workflow를 최소화한다.

### 개발 용이성

코드의 각 영역은 가능한 한 명확한 책임과 경계를 가져야 한다.

작은 기능을 이해하거나 수정하기 위해
프로젝트 전체를 분석해야 하는 구조를 피한다.

AI coding agent를 포함한 개발 도구가
제한된 context에서도 코드를 쉽게 이해하고 안전하게 수정할 수 있는 구조를 지향한다.

### 실용적인 번역 품질

번역 품질은 중요하다.

이미 검증된 품질 관련 로직은
비용이 크지 않다면 최대한 유지한다.

그러나 작은 품질 향상을 위해 큰 runtime 비용,
추가적인 model 호출, 복잡한 recovery,
대규모 상태 관리가 필요하다면 반드시 유지할 필요는 없다.

---

## 5. 의도적인 Trade-off

RoverCMT는 모든 입력과 상황에서 완벽하게 동작하는 것을 목표로 하지 않는다.

다음과 같은 trade-off를 받아들일 수 있다.

- 일부 edge case 실패
- 일부 OCR 오류
- 일부 번역 누락
- 일부 layout 품질 저하
- 기존 기능 제거
- 기존 workflow와 다른 결과
- 기존 프로젝트와의 compatibility 포기

그 대가로 다음을 얻는 것을 목표로 한다.

- 빠른 처리
- 작은 코드베이스
- 단순한 pipeline
- 낮은 유지보수 비용
- 낮은 분석 및 context 비용
- 쉬운 문제 추적
- 쉬운 기능 추가

Trade-off가 발생하는 경우
무엇을 얻고 무엇을 잃는지 확인한 뒤 결정한다.

---

## 6. 결과물 중심 설계

내부적인 workflow 상태와
결과물을 생성할 수 있는 조건을 가능한 한 분리한다.

자동 pipeline이 결과물 생성에 필요한 데이터를 만들었다면
수동 검토 여부와 관계없이 결과물을 생성할 수 있는 방향을 기본으로 한다.

중간 상태 관리 자체가 목적이 되어서는 안 된다.

---

## 7. 확장 가능한 Core

RoverCMT의 핵심 번역 기능은
특정 UI 또는 외부 interface에 종속되지 않는 방향을 지향한다.

번역 pipeline과 사용자 interface 사이에 명확한 경계를 두어,
동일한 핵심 기능을 다양한 interface에서 사용할 수 있도록 한다.

외부 연동을 위해 핵심 pipeline의 구조를 불필요하게 복잡하게 만들지는 않는다.

---

## 8. 성공 기준

RoverCMT의 성공은 기존 프로젝트의 모든 기능을 재현하는 것으로 판단하지 않는다.

다음 질문을 기준으로 판단한다.

- 입력으로부터 자동으로 결과물이 생성되는가?
- 결과물을 얻기까지 불필요한 작업이 적은가?
- 전체 처리 시간이 충분히 빠른가?
- 실패한 부분과 원인을 쉽게 확인할 수 있는가?
- 코드를 이해하고 수정하기 쉬운가?
- 제한된 context로도 특정 영역을 분석하고 수정할 수 있는가?
- 새로운 기능을 추가하기 위해 불필요하게 넓은 영역을 변경하지 않아도 되는가?
- 핵심 기능이 특정 interface에 과도하게 종속되어 있지 않은가?

RoverCMT는 기능의 양보다 이러한 목표를 우선한다.
